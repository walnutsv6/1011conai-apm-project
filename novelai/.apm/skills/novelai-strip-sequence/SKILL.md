# NovelAI Strip Sequence (undressing stage ladder)

Sub-skill of `novelai-imagegen`, sibling of `novelai-variations`. It only **designs and batches the prompts**; estimates, cost decisions, authentication and live calls belong to the `novelai-imagegen` runner. Read `../novelai-imagegen/SKILL.md` first (its topless/nude section governs this skill) and the guideline `../novelai-imagegen/references/sexual_content_guidelines.md` **before** proposing anything. If the request deviates from the guideline (minor character, sex acts, forced/unwilling framing, public place, nude-only set), stop and say so instead of building it.

## Concept

Each image is `character x stage x (pose) x mode (x nude composition)`. The stage is the only axis that changes the clothes, so differences between neighbours are attributable and the set reads as one continuous sequence.

- **Character**: fixed block (appearance incl. a bangs tag, base expression, private scene, body) plus a **fixed seed per character**.
- **Stage**: an ordered step with a `class`, a label, per-character outfit tags, and a negative that keeps already-removed items out.
- **Pose mode**: `fixed` (one pose for every stage, best consistency) or `per_stage` (each stage names its own pose, e.g. the undressing gesture).
- **Mode**: `bg` (private scene) and `transparent` (background replaced only), like `novelai-variations`.

Stage classes decide how a stage is handled:

| class | meaning | agent generates? | rating tag |
| --- | --- | --- | --- |
| `clothed` | fully dressed | yes | defaults.rating (stage `rating` overrides) |
| `partial` | clothes coming off, nothing exposed | yes | same |
| `underwear` | underwear visible | yes | same |
| `topless` | breasts exposed, bottom covered | **no, user runs script** | `rating:explicit, nipples` |
| `bottomless` | groin visible, breasts covered | **no, user runs script** | `rating:explicit` |
| `nude` | fully nude | **no, user runs script** | `rating:explicit, nipples` |

Ratings (age labels) are deliberately not shown in outputs.

## Hard rules (from the project guideline)

- Characters are adults: `defaults.base_tags` keeps an adult tag and `common_negative` keeps `child, loli`. `build_requests.py` aborts if they are removed. State the characters' adult status when proposing them; original adult characters (inspired-by, not reproductions of existing ones). Treat costumes such as school uniforms as adult cosplay.
- The sequence must start dressed and include clothed/partial/underwear stages. A nude-only set is out of scope (the script aborts).
- Self-directed, non-sexual-act framing only. Never add sex acts, bodily fluids, forced/unwilling cues, or genital detail / pubic hair. Hands or small props over the breasts/groin are fine. Undressing gestures (taking off a jacket, sliding a strap) are fine.
- Backgrounds from `underwear` onward must be private, hard-to-enter spaces (bedroom, changing room, hotel room, own room...). Set `scene_private: true` per character; the script aborts otherwise. Never use streets, public venues, or a place a third party could walk in on.
- Nude/bottomless stages need a `crotch` choice per stage: `covered` (hand or small prop hides the groin), `open` (groin unobscured, no genital detail / pubic hair), or `both`. Ask the user for each such stage. `both` is the guideline default when no pose is specified.
- Negative prompts for exposed classes include `uncensored` plus exclusions for genitals and pubic hair (`defaults.exposed_negative`). They do not guarantee the result, so the user must look at every generated image (age impression, character consistency, composition, background, excluded elements).
- **Never run, estimate, or generate topless/bottomless/nude requests yourself.** Write the requests and the run scripts, hand over the command, and stop. Only clothed/partial/underwear requests are generated by the agent.

## Workflow

In the commands below, `<skills-root>` is the installed skills directory (`.claude/skills` for Claude, `.agents/skills` for Codex/Copilot).

1. **Hear the requirements, then propose candidates.** Ask for what is missing:
   - Theme / concept and use (game reward, gravure CG set, both); the characters (or propose adult original ones, each with a bangs tag and a fixed seed).
   - **Number of stages** (the user decides every time).
   - **Pose mode**: `fixed` or `per_stage`. If `fixed`, propose 3-5 pose candidates and let the user pick one; if `per_stage`, propose a pose for each stage. Flag poses whose arms conflict with `covered` composition or with the undressing gesture.
   - **Worn items, in detail** (ask per character; do not assume). Go layer by layer, top to bottom, and confirm each item's type, colour, material/pattern, length/shape, and accessories. Checklist:
     - Outerwear / tops: jacket, cardigan, blouse, shirt, dress (collar, sleeves, buttons, ribbon, tie).
     - Bottoms: skirt (length, pleats), shorts, pants; legwear: thighhighs, pantyhose, socks (colour, length), garter belt.
     - Underwear: bra and panties (colour, lace, style); swimwear if the theme calls for it.
     - Footwear, gloves, and accessories (hair ribbon/ornaments, choker, glasses, jewelry): which stay on to the end and which come off at which stage.
     - Which items are **kept on** in the nude stage (e.g. thighhighs, ribbon). Write them into that stage's tags so they do not drift.
     Summarise the confirmed list back to the user as a layer table before moving on; it becomes `characters.<name>.stages.dressed` and the base for every later stage.
   - **Level of detail of the in-between undressing** (ask; offer the options with a recommendation):
     - *Coarse*: one stage per garment (few stages, big jumps).
     - *Standard*: per garment, with one half-removed state for the main items (e.g. jacket slipping off shoulders, blouse unbuttoned).
     - *Fine*: several steps per garment (hand on the button, half-unbuttoned, sliding off a shoulder, holding the hem, unclasping), the gesture itself pictured. Build it at the granularity of the reference ladder in [references/prompt-assembly.md](references/prompt-assembly.md#fine-ladder-reference): about 15-18 stages for a layered outfit (outerwear, blouse, skirt, bra, panties), with separate stages for the gesture (hand on cardigan, untying the ribbon, hand on the zipper, unhooking the bra), the half-removed state (slipping off shoulders, skirt around the thighs, bra falling off the shoulders) and the removed state, so no step removes two garments and the jump from underwear to topless to nude is never abrupt.
     Also ask whether the gesture should be visible (hands undressing) or only the resulting state, and whether to keep small details between steps (hair, accessories, expression change such as blush growing). The answer, together with the stage count, decides how many `partial` stages are inserted. If the stage count the user gave does not fit the chosen detail level, say so and propose a number.
   - **Stage ladder**: propose a removal order built from the confirmed worn items and detail level above, with ID, one-line meaning, class, draft outfit tags and the negative tags that keep removed items out. Use `AskUserQuestion` or a plain list; the user's tags win verbatim. Do not build until confirmed.
   - **Facing direction (front / back)** for every stage where underwear, a bra or a bikini (top or bottom) is taken off, and for every stage after it (bra off, topless, panties down, nude, extra nude poses). Ask per stage with `AskUserQuestion`; never decide it yourself. Offer: front, back (turned away, looking back), or both (two files for the same stage). Recommend back for the gesture of unhooking a bra / untying a strap so the clasp or knot is visible. Record the answer in the stage pose tags (`from behind, looking back, back turned`) and label (`(背面)`). Ask again when the user adds or revises a stage; an earlier answer does not carry over.
   - **Nude composition** (`covered` / `open` / `both`) for each nude/bottomless stage. A back-facing nude stage hides the groin, so `open` alone is enough there.
   - **Private scene** per character, and modes (`bg`, `transparent`, or both).
   - Example spec: [examples/spec.example.json](examples/spec.example.json). Treat it as inspiration, not defaults.
2. **Write the spec** as JSON, e.g. `output/novelai-imagegen/<project>/spec.json` (stage ids use `[A-Za-z0-9_]` only; they become part of file names).
3. **Build the requests**:
   ```bash
   python <skills-root>/novelai-strip-sequence/scripts/build_requests.py --spec <spec.json> --project-dir output/novelai-imagegen/<project> [--user-run-dir user-run-scripts] [--only mia] [--stage jacketoff] [--rating sensitive] [--suffix v2]
   ```
   - Agent-generated stages -> `<project>/requests/`.
   - Script-only stages -> `user-run-scripts/<character>-<theme>/requests/` plus `run.ps1` and `run.sh` there (the layout required by `novelai-imagegen`; never put them under `output/`). Create a new folder for a new request; do not mix into an old one.
   - Also writes `<project>/manifest.json` (every expected cell, in order) and `<project>/prompts.md`.
   - Existing request files are never overwritten; use `--suffix v2` for a revision.
4. **Review `prompts.md`** with the user, especially the prompt of one stage per class and both nude compositions.
5. **Pilot, then batch the agent stages** (clothed / partial / underwear only). Estimate, then generate, one request at a time, sending output into `<project>/images` (the request's `output.character` creates the per-character folder):
   ```bash
   for f in <project>/requests/*.request.json; do
     python <skills-root>/novelai-strip-sequence/scripts/has_output.py --request "$f" --out-dir <project>/images && continue
     uv run <skills-root>/novelai-imagegen/scripts/novelai_image.py estimate --request "$f" && \
     uv run <skills-root>/novelai-imagegen/scripts/novelai_image.py generate --request "$f" --out-dir <project>/images
   done
   ```
   **Skip what already exists**: `has_output.py` exits 0 when `images/<character>/<basename>-seed<seed>[-N].png` is already there, so the loop skips it. The runner does not refuse to overwrite; it writes a second copy with a `-2` suffix, so a pilot image must not be generated again by the batch. To redo an image on purpose, move the old take to `superseded/` first (or build with `--suffix v2`). Respect the zero-Anlas / cost policy of `novelai-imagegen`. Inspect every output, fix with a *targeted* change (see Fix patterns), move old takes to `images/<character>/superseded/` together with their `manifest/<stem>.json`.
6. **Hand over the user-run scripts.** Give the command and the key setup, then stop:
   - PowerShell: `$env:NOVELAI_API_KEY = "<key>"` then `powershell -ExecutionPolicy Bypass -File user-run-scripts/<character>-<theme>/run.ps1`
   - bash: `export NOVELAI_API_KEY=...` then `bash user-run-scripts/<character>-<theme>/run.sh`
   - The key stays in the user's shell session, never in a file. The script validates the environment, skips requests whose image already exists (`has_output.py`), estimates each request before generating, and writes to `<project>/images/<character>/`.
   - Remind the user to check each result by eye (list above).
7. **Build the index page** (after every batch, redo, and after the user has added their images):
   ```bash
   python <skills-root>/novelai-strip-sequence/scripts/build_index.py --project-dir output/novelai-imagegen/<project> [--title "<title>"]
   ```
   One page per project: per character a **slideshow viewer** (current image centred at the top, 640px wide, with the control panel directly below it; play / pause / step / speed; mode switch; nude composition preference `covered` / `open` / `all`; missing frames are skipped) and a stage table (columns = stages in order, rows = modes). Stages without an image show a dashed frame ("ユーザー生成枠" for script-only stages), so the frame for topless/nude exists before they are generated. Latest `vN` wins; `superseded/` is ignored.
8. **Report**: index.html path, counts (characters x stages x modes), seeds, estimated Anlas for agent-generated images, the user-run script paths and what the user still has to run. Do not claim success for images not inspected, and do not claim anything about user-run images.

## Spec essentials

See [references/prompt-assembly.md](references/prompt-assembly.md) for the exact prompt/negative order and every spec key. In short:

- `defaults`: model, orientation, steps, scale, rating, `modes`, `pose_mode`, `fixed_pose`, `base_tags`, `composition`, `gaze`, `style`, `covered_tags`, `exposed_expression` (default `embarrassed, shy, blush`, added from topless onward), `clothed_negative`, `exposed_negative`, `common_negative`, `require_zero_anlas`.
- `poses`: id -> `{tags, expression, ...}`.
- `stages`: ordered list of `{id, label, class, pose?, crotch?, negative?, rating?}`.
- `characters.<name>`: `seed`, `appearance` (with bangs), `expression`, `scene`, `scene_private`, `body`, `negative`, `stages` (id -> outfit tags), `overrides`.

## Fixed conventions

- Model `nai-diffusion-5-full`, 832x1216 portrait, steps 28, scale 5.0, samples 1; `cowboy shot` + `looking at viewer`; negative `full body, wide shot`.
- Seed fixed per character across all stages.
- Transparent version replaces **only** the background segment; `straight_alpha` and `tag_hint_transparent_background` on; mode negative `scenery, background, outdoors`.
- File name: `<character>-<stage>-<pose>-<bg|transparent>[-covered|-open][-note][-vN]-seed<seed>.png`; metadata JSON in the `manifest/` subfolder.

## Fix patterns (change one thing, keep the seed)

| Symptom | Fix |
| --- | --- |
| Removed garment reappears | Add it to that stage's `negative` (and every later stage's). Per-character: `overrides` with `append_negative`. |
| Next stage shows too much / too little | Edit only that stage's outfit tags; never reorder the rest of the prompt (it changes the composition under a fixed seed). |
| Pose drifts between stages | Use `pose_mode: fixed`; or keep `per_stage` poses close (same stance, only arms change). |
| `covered` composition shows the hand in the wrong place | Change `defaults.covered_tags` or override that stage with `append_stage` (e.g. `holding pillow`), small props only. |
| Bangs / hair colour / skin drift | Same fixes as `novelai-variations` (bangs tag in `appearance`, opposite colours in the character `negative`); regenerate the whole character with the same seed. |
| Transparent version has leftover scenery | Strengthen the negative; if still bad, `remove_background` Director Tool (paid, needs confirmation). |
| Eyes closed by an expression tag | Drop that expression for the stage via `replace_pose_expression` and add `closed eyes, half-closed eyes` to the negative. |
| Garment colour/gradient drifts between stages (e.g. navy skirt turns light blue) | Prefix the tag with `solid dark <colour>` in the drifting stages only and add `light <colour> <garment>, gradient <garment>, two-tone <garment>` to those stages' `negative`. |
| Back-facing stage looks the other way (mirrored vs. its neighbours) | Compare the stages side by side, note which shoulder the neighbours look over, and add `looking back over left/right shoulder, head turned to the left/right` to that pose. Side tags are weak; if it flips again adjust the wording rather than flipping the image (flipping breaks prompt/background correspondence). |
| A pose must differ between `covered` and `open` (e.g. raised knee covering vs. not covering the groin) | Keep the shared pose in `poses`, and add two `overrides` with `match: {stage, variant}` and `append_stage` (e.g. `knee pulled toward chest, raised leg covering crotch` / `raised leg turned out wide to the side`) plus distinct `note` slugs. |

**Revising user-run (topless/bottomless/nude) stages**: never overwrite the user's images or request files. Move the old takes (png + `manifest/<stem>.json`) to `images/<character>/superseded/` and the old request JSON to `requests_superseded/`, then change the spec `theme` to a new slug (e.g. `hotel-room-knee2`) and run `build_requests.py --stage <changed stages>` so the revised requests land in a new `user-run-scripts/<character>-<theme>/` folder with its own `run.ps1` / `run.sh`. Delete from that new folder any request of an unchanged variant that `--stage` also wrote (images exist, so the user must not rerun them). Then rebuild `index.html` after the user has run the script.

Override keys: `replace_stage`, `append_stage`, `replace_pose_expression`, `replace_composition`, `append_appearance`, `append_negative`, `append_body`, `seed`, `note`; `match` keys: `stage`, `mode`, `variant`.

## Output layout

```
output/novelai-imagegen/<project>/
  spec.json
  manifest.json          # expected cells in stage order (build_requests.py)
  requests/              # clothed / partial / underwear requests (agent runs these)
  images/<character>/    # png (runner output), manifest/<stem>.json, superseded/
  prompts.md
  index.html             # slideshow viewer + stage table (build_index.py)
user-run-scripts/<character>-<theme>/
  run.ps1, run.sh        # user-run; writes into <project>/images
  requests/              # topless / bottomless / nude requests
```
