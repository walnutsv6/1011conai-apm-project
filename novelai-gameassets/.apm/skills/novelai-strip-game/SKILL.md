# NovelAI Strip Game Assets

Sub-skill of `novelai-imagegen`, built on `novelai-strip-sequence`. It ships in the supplementary `novelai-gameassets` package, which depends on the `novelai` package; both skills must be installed next to this one (same skills directory). It **designs and batches the requests** for game assets; estimates, cost decisions, authentication and live calls belong to the `novelai-imagegen` runner. If `../novelai-imagegen/`, its guideline file or `../novelai-strip-sequence/` is missing, do not write any topless/nude prompt; tell the user to install the `novelai` package and stop. Before proposing anything, read:

1. `../novelai-imagegen/SKILL.md` (its topless/nude section governs this skill),
2. the guideline `../novelai-imagegen/references/sexual_content_guidelines.md` (and `multi_character_guidelines.md` for a key visual with several characters),
3. `../novelai-strip-sequence/SKILL.md` — its hard rules, worn-item hearing, facing rule and fix patterns all apply here unchanged.

If the request deviates from the guideline (minor or minor-looking character, sex acts, forced/unwilling framing, public place, nude-only set), stop and say so instead of building it.

## Concept

Each image is one **cell**: `character x stage x (expression | special pose) x mode x (crotch variant)`, built by a **method**.

- **Stage** (`stages[]`, in order) has a `role`:
  - `main`: a stage the game rests on (dressed, jacket off, underwear...). Gets every expression in `expression_set` and the special poses whose scope includes it.
  - `transition`: an in-between undressing frame, shown while switching from the previous main stage to the next (the gesture of taking the garment off). One expression only (`transition_expression`, default `shy`), no special poses. Default one frame per boundary; add more only where the change is large (bra, panties). `duration_ms` per frame (default 450).
- **Expression**: face tags only (`expressions.<id>.tags`), swapped in for the pose expression. `normal` is required (inpaint parent and fallback).
- **Special pose**: game-specific pose with its own fixed expression and a stage scope (`all`, `to_underwear`, or a list of main stage ids); may set `composition` and `orientation` (cut-ins).
- **One-shot**: `icon` (cropped from the dressed normal sprite at export, not generated), `title` (clothed key visual, bg mode), `reward` (clear CG; nude = user-run, private scene).
- **Method**:
  - `seed`: every cell regenerated with the character's fixed seed; `transparent` mode uses straight alpha. Free under the zero-Anlas conditions; small drift between stages.
  - `inpaint`: a base plate (first main stage, flat grey background) is generated, and every later cell repaints only a masked region: main stage <- previous main stage (clothes region), expression <- same stage's normal plate (face), transition <- previous main stage (clothes + face). **NovelAI inpainting cannot output transparency**, so every plate is cut out afterwards (`remove_bg.py`). A stage whose facing differs from its parent starts a new base plate (the body turns; inpainting cannot do that). Special poses and one-shots are seed-method only.
  - `mixed`: each cell kind from one of the two (`method_by_kind`; default sprites = inpaint, transitions / special poses / one-shots = seed). Main stages and expressions line up pixel for pixel, while gestures and janken hands stay natural; transitions may shift slightly against the sprites.
  - The first project of a character builds both (`methods: ["seed", "inpaint"]`) and the user picks `seed`, `inpaint` or `mixed` after the pilot. Show the trade-off with numbers and face crops, not only full sprites. In the first pilot (cowboy shot, 4 expressions) the user finally chose `seed`: each seed face is a clean, whole drawing, while face inpainting left the face slightly soft and re-drew the bangs over the eyes differently per expression; the price is that the whole body shifts between expressions (silhouette overlap about 0.94 against 0.998 for inpaint).

Cell classes follow `novelai-strip-sequence` (`clothed`, `partial`, `underwear` = agent; `topless`, `bottomless`, `nude` = user-run). A transition's class is what is **visible in that frame** (bra held against the chest = `underwear`; nipples visible = `topless`).

## Hard rules

Everything in `novelai-strip-sequence` "Hard rules" applies (adult tags and `child, loli` guards are enforced by its `validate()`, which this skill calls; start dressed; self-directed framing only; no sex acts, genital detail or pubic hair; private scene from underwear on in bg mode; `crotch` choice per nude/bottomless stage; `uncensored` + exclusions in exposed negatives). In addition:

- **Never run, estimate, generate, inpaint, cut out, or otherwise process topless/bottomless/nude cells yourself.** They go to `user-run-scripts/<character>-<theme>[-inpaint]/` with `run.ps1` / `run.sh`; the inpaint script also makes the masks of new base plates and cuts out each image. You hand over the command and stop.
- **Every asset is tied to a game event** (`events`): this is the "reward for a play result" position the guideline requires. Do not build assets that no event or one-shot uses.
- **Game-side backgrounds are covered by the guideline too.** Sprites are transparent, but tell the user that the background the game composites them on must also be private from underwear on (a mahjong table in a private room, not a parlour; no quiz studio with an audience).
- **Age classes are self-imposed production categories, not official ratings** (`all` / `12rec` / `15rec` / `15` / `18`, from the guideline's 自主規制レーティング基準). Say so whenever you show them; the person publishing makes the final check. Mark costume stages with `revealing: true` (bunny, high-leg, bikini -> 12rec) and liquid stages with `fluids: true` (-> 18).
- Facing (front/back) is asked per stage for every bra / bikini / panties removal stage (main **and** transition) and every stage after it; never decide it yourself (memory rule shared with strip-sequence).
- Under the zero-Anlas policy, stop on any nonzero inpaint estimate as the runner says. `remove_background` (Director Tool) is never free; the default cut-out is local (`rembg`, isnet-anime) with `chroma` as fallback.

## Workflow

`<skills-root>` is the installed skills directory (`.claude/skills` for Claude).

1. **Pick the game preset** from [references/presets.md](references/presets.md) (`yakyuken`, `mahjong`, `quiz`, `generic`; files in `references/presets/`). Show its defaults as a table: stage count (default + range), expressions, special poses and their stage scope, framing, modes, events, one-shots. Ask what to change; the user decides the stage count every time.
2. **Characters** (adult, original or inspired-by): reuse a `character.json` (novelai-character-extract) or an earlier spec's character block; fix the seed per character. Several opponents go in one spec.
3. **Worn items and stage ladder**: run the strip-sequence hearing (layer table, detail level). Map main stages to the game rule (yakyuken: one loss = one main stage) and put one `transition` between neighbouring mains (more only where the change is large). One garment or one gesture per main step; if the stage count does not fit the outfit, say so and propose a number.
4. **Facing and crotch**: ask facing per stage for bra/panties removal and later stages (main and transition), and `covered` / `open` / `both` per nude/bottomless stage. Remind the user that a facing change restarts the inpaint chain.
5. **Write the spec** (`output/novelai-imagegen/<project>/spec.json`, see [references/asset-spec.md](references/asset-spec.md) and [examples/spec.example.json](examples/spec.example.json)). Copy the preset values in explicitly; the spec is the source of truth. Give transitions a gesture `pose` and outfit tags that show the garment coming off; give inpaint stages `inpaint_regions`.
6. **Build the requests**:
   ```bash
   python <skills-root>/novelai-strip-game/scripts/build_game_requests.py --spec <spec.json> --project-dir output/novelai-imagegen/<project> [--method seed|inpaint|mixed] [--only meru] [--stage s1,s2] [--suffix v2]
   ```
   Writes `requests/<method>/` + `order.txt` (agent cells), `user-run-scripts/<character>-<theme>[-inpaint]/` (user cells), `cells.json`, `prompts-<method>.md`. Existing request files are never overwritten; after a spec fix, `--refresh-unrun` rewrites only requests whose image does not exist yet. Review the prompts with the user (one cell per class, a transition, a special pose, both crotch variants). Revisions: [inpaint-pipeline.md "Revising a take"](references/inpaint-pipeline.md#revising-a-take).
7. **Pilot** (first project of a character): the agent-generated part of the first 2-3 main stages and their transitions, `normal` + one more expression, with both methods, plus one special pose. Run in `order.txt` order (inpaint children need their parent), skipping existing images:
   ```bash
   while read -r n; do n="${n%$'\r'}"; f=<project>/requests/<method>/$n
     python <skills-root>/novelai-strip-sequence/scripts/has_output.py --request "$f" --out-dir <project>/images && continue
     uv run <skills-root>/novelai-imagegen/scripts/novelai_image.py estimate --request "$f" && \
     uv run <skills-root>/novelai-imagegen/scripts/novelai_image.py generate --request "$f" --out-dir <project>/images
   done < <project>/requests/<method>/order.txt
   ```
   For the inpaint method, after the base plate exists run `make_masks.py` and look at the `_overlay-*.png` files before any inpaint request; after generating, cut out:
   ```bash
   python <skills-root>/novelai-strip-game/scripts/make_masks.py --project-dir <project> --character <c>
   uv run <skills-root>/novelai-strip-game/scripts/remove_bg.py --cells <project>/cells.json --character <c> [--method chroma]
   ```
   Compare with the preview's overlay (位置ずれ), face consistency, cut-out edges and estimates; record the user's choice (`methods` in the spec, plus `method_by_kind` for `mixed`), then rebuild without `--method` so `order.txt` and the user-run folders hold only the chosen cells (a full build rewrites `order.txt`; move never-run user-run folders of the pilot build aside first). See [references/inpaint-pipeline.md](references/inpaint-pipeline.md).
8. **Batch the agent cells** of the chosen method; inspect every image (age impression, consistency, removed garments not returning, background, excluded elements, hands in special poses); fix with one targeted change (strip-sequence Fix patterns; inpaint fixes in inpaint-pipeline.md). Move rejected takes to `images/<c>/superseded/` with their `manifest/<stem>.json`.
9. **Hand over the user-run scripts** (PowerShell: `$env:NOVELAI_API_KEY = "<key>"` then `powershell -ExecutionPolicy Bypass -File user-run-scripts/<c>-<theme>/run.ps1`; bash: `export NOVELAI_API_KEY=...` then `bash .../run.sh`). Inpaint user cells need their agent-generated parents first. Remind the user to check every result by eye.
10. **Preview** (after every batch and after the user's run):
    ```bash
    python <skills-root>/novelai-strip-game/scripts/build_preview.py --project-dir output/novelai-imagegen/<project>
    ```
    Per character and method: simulator (event buttons; advancing plays the transition frames then shows the next stage with the `after_strip` expression; missing expressions fall back to `normal`), overlay compare of two cells, and the stage x expression / special-pose table with dashed frames for missing and user-run cells.
11. **Export** for the game:
    ```bash
    python <skills-root>/novelai-strip-game/scripts/export_assets.py --project-dir output/novelai-imagegen/<project> --method seed|inpaint|mixed --max-age 15rec
    ```
    Writes `export/<method>-<max-age>/<character>/*.png` + `assets.json` (schema in asset-spec.md). Export one folder per edition the game ships (e.g. `15rec` and `18`).
12. **Report**: preview path, cell counts (agent / user-run) per character and method, seeds, estimated Anlas, user-run script paths and what the user still has to run, export folders. Do not claim anything about images you did not inspect or that the user generated.

## Output layout

```
output/novelai-imagegen/<project>/
  spec.json, cells.json, prompts-<method>.md, index.html
  requests/seed/, requests/inpaint/      # agent cells + order.txt (requests_superseded/ for replaced ones)
  masks/<character>/<group>/             # inpaint masks (+ _overlay-*.png); group = stage that started the chain
  images/<character>/                    # runner output, manifest/, superseded/, cutout/ (inpaint cut-outs)
  export/<method>-<max-age>/             # assets.json + <character>/*.png
user-run-scripts/<character>-<theme>[-inpaint]/
  run.ps1, run.sh, requests/ + order.txt # topless / bottomless / nude cells (user only)
```

File names: `<character>-<stage>-<pose>-<transparent|bg|plate>[-covered|-open][-note]-<expression>[-vN]-seed<seed>.png`; special poses use the pose id and no expression; one-shot stages are `os_<id>`.
