# ROMごとのドライバー解析

## 解析の分離

ゲーム固有の部分は「曲/SE番号 → レジスタ転送の時系列」。共通部分は「レジスタ転送 → 制御タイマー → Pyxelの音符/音量/音色」。付属コードが担当するのは後者。音楽データの符号やポインタ配置はROMごとに異なる。

最初に原本を読み取り、ROMサイズ、タイトル、版、SHA-256、ヘッダー、MBCとROMバンクを記録する。CPUアドレス `$4000` とファイルオフセットはバンクに依存する。版違いで既知のアドレスを流用しない。

## ドライバーを読む順序

1. NR10～NR52と波形RAM `$FF30～$FF3F` の転送箇所、VBlank/タイマー割り込みから呼ばれる更新ルーチンを探す。チャンネルに対するアドレス間接転送も調べる。
2. ゲーム側で曲/SE要求レジスタへ書く箇所を逆にたどり、開始条件・消去・優先順位を記録する。曲停止、ポーズ、SE終了後のBGM復帰を区別する。
3. 曲ヘッダー、フレーズ列、ジャンプ、終端、音符長テーブル、周波数表、楽器パラメーターを特定する。線形逆アセンブルがデータを命令として表示していても、ROMの生バイトと参照元の命令から解釈する。
4. 更新カウンターの減算順と初期値を移植する。要求フレームで即更新するか、次フレームから更新するかでSE長や音の切り替えがずれる。
5. レジスタ転送をフレーム/時刻つきで出すアダプターを作る。CPUを移植する必要はない。解析補助としてCPUや既存エミュレーターを使う場合も、実行時のゲームへROM依存を持ち込まない。

## 音符以外に必要な情報

| 音源 | 記録するもの |
| --- | --- |
| 矩形波CH1/CH2 | デューティ比、周波数、初期音量と増減、長さ有効、トリガー、CH1スイープ |
| 波形CH3 | DACのON/OFF、波形RAMの16バイト、出力段階、周波数、長さ有効、トリガー |
| ノイズCH4 | クロック分周、7/15bit幅、初期音量と増減、長さ、トリガー |
| 全体 | NR50/NR51/NR52、停止・ポーズ・所有権の切り替え、更新周期 |

レジスタの高ビットは周波数だけではない。周波数値は11bit、上位側のbit6は長さ有効、bit7はトリガー。NR12/NR22の下位ビットを波形の種類と誤解しない。波形RAMは各バイトの上位・下位ニブルを順に展開し、32個の0～15の値として保存する。

## 曲の長さとループ

- どれかのチャンネルが終端に達すると全チャンネルを止めるドライバーがある。各パートを単独で末尾まで読むと、隣の表を音符と誤読することがある。
- BGMのノイズパートは短いパターンを他パートと独立に繰り返すことがある。全パートを同じ長さに無理に合わせない。
- ループはジャンプ先や更新状態の反復で判断する。状態比較から、使われないカウンターなど出力へ影響しない値を外す。ただし楽器・休符・周波数・音符カウンターは必要。
- 最初の再生と後続ループで冒頭状態が違う場合は、冒頭と周期区間を分ける。効果音終了後に冒頭区間を毎回繰り返さない。
- ドライバーが「長さ指定後に1バイトだけ読む」なら、そのバイトも長さ指定のように見えても原作の制御に従う。音楽データを親切に修正してしまわない。

## ゲーム側のSE制御

SEのチャンネル占有と鳴動時間は、音量が0になった時刻とは別に保つ。低優先度のSEが、既に無音の高優先度SEを上書きできるとは限らない。

複数チャンネルにまたがるSEは、1つのイベントに属する遅延パートとして扱う。途中で上書きされた場合は、後から鳴る予定だったパートも取り消す。BGMは進行中の曲位置へ戻し、リスタート・メニュー遷移・ポーズ解除で古いSEの予約を残さない。

これらのルールはゲーム固有。今回のTetrisのガード表や「波形SE中にBGM全体を止める」挙動を、他のゲームの規則として固定しない。
