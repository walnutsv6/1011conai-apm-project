# 検証と再現精度

## 精度を主張する根拠

1. 独立した基準でドライバーを照合する。元ROMを命令実行した転送記録、信頼できるエミュレーターの記録、命令を追って作った別実装などを用いる。変換器の出力を同じ変換器の出力と比較するだけでは原作との一致は証明できない。
2. 全レジスタ・全フレーム・転送順を比較する。初期化、音符の更新、波形RAM、休符、長さ、SEの連鎖、停止、少なくとも次のループを含める。最終的な音高だけの一致では楽器や減衰の誤りが残る。
3. `.pyxres` 内の音符・音量・埋め込み音色列と変換結果を比較する。標準プレビュー音色との違いを意図的なものと確認する。
4. 実際のPyxelで曲選択、空チャンネル、冒頭→ループ、OFF、ポーズ、SE併奏・復帰、リスタート、画面遷移を確認する。ネイティブのリソース読み込みで配列長や独自音色の扱いが変わることがある。
5. 開発中だけ一時WAVへレンダリングし、非無音区間の振幅・波形・耳での印象を確認してよい。PCMファイルをゲームの再生リソースに含める必要はない。
6. ROM、アダプター、逆アセンブルを含めない配置で起動・再生する。抽出時にだけ必要なモジュールが、実行時importへ混ざっていないことを確認する。

## 付属コードの自己検証

```powershell
.\.venv\Scripts\python.exe <skill-directory>/scripts/self_test.py
```

この検証は共通コードのタイマー・出力形式・Pyxelとの接続を確かめる。対象ROMのアダプターが正しいことは、対象プロジェクトで別に確かめる。

## 共通変換器の精度範囲

共通モデルは通常のDAC、長さ、包絡線、CH1スイープと固定位相の512Hzフレームシーケンサーを扱う。GBのPCMレンダラーやCPUエミュレーターではない。

120Hzの制御列、半音単位の音高、0～7の音量へ丸める。細かなビブラート/スイープは変化が消えることがある。ノイズのクロックはPyxelの発振器へ近似変換する。矩形波・波形メモリーのサンプルは保持するが、APUの位相、実機のアナログフィルター、ステレオ出力は一致しない。NR50/NR51は記録するが、このモデルでは左右の混合とマスター音量を再現しない。

GBのDACの特殊挙動、包絡線の途中書き換え、フレームシーケンサー境界での長さ更新、波形RAMへの再生中アクセス、DIVリセット、GBC倍速モードのタイミングは限定的。対象ドライバーが利用していると分かった場合にモデル/アダプターを拡張し、影響を説明する。今回のTetrisで高精度だったことだけから他の全ROMに同じ精度を主張しない。

GBの音源で鳴る音と、Pyxelの標準4音色で近似した音は大きく違う。PCMの有無を結論づける前に、波形RAM・エンベロープ・ノイズ幅・周波数の動的転送を調べる。
